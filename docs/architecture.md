```

 │                                               │          │                  │        │           │
 │  ktc_service (служба на Dart, LocalSystem)    │  REST    │  Firestore       │  SDK   │ Родитель- │
 │   ├─ ProcessWatcher: запуск/завершение игр    │◄────────►│  Auth            │◄──────►│ ское      │
 │   ├─ AppMatcher: игра или нет (ktc_core)      │  HTTPS   │  Functions       │        │ приложение│
 │   ├─ UsageTracker: учёт времени (ktc_core)    │          │  Messaging (push)│        │           │
 │   ├─ LocalStore: JSON в ProgramData           │          └──────────────────┘        └───────────┘
 │   └─ CloudSync: синхронизация (этап 2)        │
 │            ▲ named pipe \\.\pipe\KidsTimeControl
 │            ▼                                  │
 │  ktc_agent (Flutter, трей, сессия польз.)     │
```

## Компоненты ПК

Всё написано на Dart: служба — консольная программа на чистом Dart, агент и родительское
приложение — на Flutter. Общая логика вынесена в пакет `ktc_core` и используется всеми тремя.

### Пакет `ktc_core` (`packages/ktc_core`)
Чистый Dart без WinAPI, UI и Flutter: работает на любой платформе и полностью покрыт тестами.

| Модуль | Назначение |
|---|---|
| `models.dart` | дети, правила игр, лимиты (соответствуют схемам в `shared/schema`) |
| `app_matcher.dart` | сопоставление процесса (путь, командная строка) с правилом игры |
| `usage_tracker.dart` | учёт времени активного ребёнка, пороги предупреждений |
| `pin.dart` | хэширование и проверка PIN (PBKDF2-HMAC-SHA256) |

Этот же пакет использует Android-приложение родителя, поэтому формат хэша PIN и правила
распознавания игр реализованы один раз.

### Служба `ktc_service` (`apps/service`)
- Консольная программа на Dart, собирается в `.exe` (`dart compile exe`).
- Регистрируется службой Windows через [WinSW](https://github.com/winsw/winsw): автозапуск,
  учётная запись LocalSystem, перезапуск при сбое, журнал.
- WinAPI вызывается через пакет [`win32`](https://pub.dev/packages/win32) (FFI):
  список процессов (`CreateToolhelp32Snapshot`, `QueryFullProcessImageName`) с опросом раз
  в 1–2 секунды, командная строка через WMI, приостановка (`NtSuspendProcess`) и завершение процессов,
  named pipe для агента, `WTSQueryUserToken` + `CreateProcessAsUser` для запуска агента.
- При запуске контролируемой игры без активной сессии приостанавливает процесс и просит агента
  показать окно входа.
- Раз в секунду вызывает `UsageTracker.tick`, раз в минуту сохраняет состояние.

### Агент `ktc_agent` (`apps/agent`)
- Flutter-приложение для Windows в трее ([`tray_manager`](https://pub.dev/packages/tray_manager),
  [`window_manager`](https://pub.dev/packages/window_manager)), запускается при входе пользователя.
- Показывает окно «Кто играет?», уведомления, остаток времени. Сам ничего не решает:
  только передаёт ответы ребёнка службе.
- Если агента закрыть, служба запустит его снова.

### Родительское приложение (`apps/parent`, этап 2)
Flutter для Android (при желании и iOS), Firebase SDK (Auth, Firestore, Messaging).

### Протокол служба ↔ агент
Named pipe `\\.\pipe\KidsTimeControl`, сообщения — JSON, по одному на строку.

| Направление | Сообщение | Поля |
|---|---|---|
| служба → агент | `askLogin` | `requestId`, `appName`, `children[] {id, name}` |
| агент → служба | `login` | `requestId`, `childId`, `pin` |
| служба → агент | `loginResult` | `requestId`, `ok`, `reason` (`wrongPin`, `locked`, `noTimeLeft`, `outsideHours`) |
| агент → служба | `cancelLogin` / `logout` | `requestId` |
| служба → агент | `state` | `childId`, `childName`, `remainingSeconds`, `playing` |
| служба → агент | `warning` | `remainingSeconds` |

PIN передаётся только внутри ПК и сразу проверяется по хэшу. Доступ к pipe ограничен ACL
(SYSTEM и интерактивный пользователь).

### Локальное хранилище
`%ProgramData%\KidsTimeControl\`:
- `config.json` — дети (с хэшами PIN), правила игр, лимиты (копия из облака или ручная настройка на этапе 1);
- `usage-YYYY-MM-DD.json` — использование по детям и играм;
- `outbox/` — события для отправки в облако (этап 2).

## Облако (этап 2)
- Родитель входит в Android-приложение через Google (Firebase Auth).
- **Привязка ПК**: приложение показывает 6-значный код, программа на ПК отправляет его в Cloud Function
  `pairDevice`. Функция проверяет код и выдаёт ПК custom token, привязанный к семье.
- ПК работает с Firestore через REST API: официального Firebase SDK для Windows-программ и Flutter Windows нет.
  Изменения лимитов ПК забирает раз в минуту.
- Статистику ПК пишет в `usage`. Агрегаты по неделям считает Cloud Function.
- Правила Firestore: родитель читает и пишет всё в своей семье; ПК пишет только `usage` и `devices/{своё id}`,
  изменить лимиты не может.

Модель данных — в [data-model.md](data-model.md), JSON-схемы — в `shared/schema/`.

## Модель угроз

| Обход | Защита |
|---|---|
| Завершить процесс или службу | у ребёнка нет прав администратора; служба перезапускается |
| Переименовать или скопировать exe игры | сверка пути, позже SHA-256 |
| Изменить системное время | обычный пользователь не может; учёт по монотонным часам |
| Играть под чужим профилем | PIN, блокировка после 5 ошибок, завершение сессии по простою |
| Отключить интернет | ПК работает офлайн; родитель видит пропуск сигналов |
| Безопасный режим, другая ОС | не защищается, это вне рамок |
