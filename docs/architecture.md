# Архитектура

```
 ┌──────────────── ПК (Windows) ────────────────┐          ┌──── Firebase ────┐        ┌─ Flutter ─┐
 │                                               │          │                  │        │           │
 │  ktc_service (служба на Dart, LocalSystem)    │  REST    │  Firestore       │  SDK   │ Родитель- │
 │   ├─ ProcessWatcher: запуск/завершение игр    │◄────────►│  Auth            │◄──────►│ ское      │
 │   ├─ AppMatcher: игра или нет (ktc_core)      │  HTTPS   │  Functions       │        │ приложение│
 │   ├─ UsageTracker: учёт времени (ktc_core)    │          │  Messaging (push)│        │           │
 │   ├─ LocalStore: JSON в ProgramData           │          └──────────────────┘        └───────────┘
 │   └─ CloudSync: синхронизация (этап 2)        │
 │            ▲ TCP 127.0.0.1:47291, JSON-строки │
 │            ▼                                  │
 │  ktc_agent (Flutter, трей, сессия польз.)     │
 │   ├─ окно «Кто играет?» + PIN                 │
 │   └─ уведомления, остаток времени             │
 └───────────────────────────────────────────────┘
```

## Компоненты ПК

Всё написано на Dart: служба — консольная программа на чистом Dart, агент и родительское
приложение — на Flutter. Общая логика вынесена в пакет `ktc_core` и используется всеми тремя.

### Пакет `ktc_core` (`packages/ktc_core`)
Чистый Dart без WinAPI, UI и Flutter: работает на любой платформе и полностью покрыт тестами.

| Модуль | Назначение |
|---|---|
| `models.dart` | дети, правила игр, лимиты (соответствуют схемам в `shared/schema`) |
| `app_matcher.dart` | сопоставление процесса (путь, командная строка) с правилом игры |
| `usage_tracker.dart` | учёт времени активного ребёнка, пороги предупреждений |
| `pin.dart` | хэширование и проверка PIN (PBKDF2-HMAC-SHA256) |

Этот же пакет использует Android-приложение родителя, поэтому формат хэша PIN и правила
распознавания игр реализованы один раз.

### Служба `ktc_service` (`apps/service`)
- Консольная программа на Dart, собирается в `.exe` (`dart compile exe`).
- Регистрируется службой Windows через [WinSW](https://github.com/winsw/winsw): автозапуск,
  учётная запись LocalSystem, перезапуск при сбое, журнал.
- WinAPI вызывается через пакет [`win32`](https://pub.dev/packages/win32) (FFI):
  список процессов (`EnumProcesses`, `QueryFullProcessImageName`) с опросом раз в 2 секунды,
  командная строка (`NtQueryInformationProcess`), приостановка (`NtSuspendProcess`) и завершение
  процессов, сессия у экрана и блокировка экрана (`WTSGetActiveConsoleSessionId`,
  `WTSQuerySessionInformation`).
- При запуске контролируемой игры без активной сессии приостанавливает процесс и просит агента
  показать окно входа. Пока экран заблокирован, никого не спрашивает: игры остаются на паузе.
- Блокировка экрана, кнопка «Выйти» в агенте и 10 минут без игр завершают сессию ребёнка.
- Учёт времени каждые 2 секунды, сохранение использования на диск, синхронизация с облаком раз
  в минуту параллельно с учётом.

### Агент `ktc_agent` (`apps/agent`)
- Flutter-приложение для Windows в трее ([`tray_manager`](https://pub.dev/packages/tray_manager),
  [`window_manager`](https://pub.dev/packages/window_manager)), запускается при входе пользователя.
- Показывает окно «Кто играет?», уведомления, остаток времени (подсказка и меню значка в трее),
  кнопку «Выйти (сменить игрока)». Сам ничего не решает: только передаёт ответы ребёнка службе.
- Запускается при входе любого пользователя (`HKLM\...\Run`: ребёнок с обычной учётной записью
  не может убрать автозапуск), один экземпляр на сессию Windows.
- Если агент закрыть, спросить «кто играет» некому, и служба закрывает игры: обойти контроль,
  убив агент, нельзя.

### Родительское приложение (`apps/parent`, этап 2)
Flutter для Android (при желании и iOS), Firebase SDK (Auth, Firestore, Messaging).

### Протокол служба ↔ агент
TCP только на `127.0.0.1:47291`, сообщения — JSON, по одному на строку (UTF-8). Код протокола
общий: `packages/ktc_core/lib/src/agent_protocol.dart`.

| Направление | `type` | Поля |
|---|---|---|
| агент → служба | `hello` | `sessionId` (сессия Windows агента), `version` |
| служба → агент | `login` | `id`, `appName`, `children[] {id, name}`, `error` (`wrongPin`, `locked`, `noTimeLeft` — почему не удалась прошлая попытка) |
| агент → служба | `loginReply` | `id`, `childId`, `pin` (без `childId` — «Отмена») |
| служба → агент | `notice` | `kind` (`minutesLeft`, `timeUp`, `noTimeLeft`), `childName`, `minutes` |
| служба → агент | `status` | `childName`, `remainingSeconds` (оба `null` — никто не играет) |
| агент → служба | `logout` | — |

Вопросы и уведомления служба отправляет агенту той сессии, что сейчас у экрана.

Почему TCP, а не named pipe: одинаково работает и тестируется на любой ОС, а безопасность от ACL
не зависит. Подключиться может любая программа на ПК, поэтому агенту ничего не доверено: служба
сама проверяет PIN (с блокировкой после 5 ошибок), а поддельный «агент» может только не дать
играть. Строки длиннее 64 КБ и незнакомые сообщения отбрасываются.

### Локальное хранилище
`%ProgramData%\KidsTimeControl\`:
- `config.json` — дети (с хэшами PIN), правила игр, лимиты (копия из облака или ручная настройка);
- `cloud.json` — привязка ПК к семье (ключ обновления входа Firebase);
- `usage/<ребёнок>_<дата>.json` — использование по дням и играм;
- `programs.json` — какие программы запускали за 2 недели (родитель выбирает из них игры);
- `logs/` — журналы службы.

Доступ к папке — только SYSTEM и администраторы (`install.ps1`).

## Облако (этап 2)

Всё работает на **бесплатном тарифе Firebase (Spark)**: Cloud Functions не используются, потому что
им нужен платный тариф Blaze. Вся проверка прав — в правилах Firestore.

- **Родитель** входит в приложение через Google (Firebase Auth) и при первом входе создаёт документ семьи.
- **ПК** входит **анонимно** через REST API Firebase Auth. Анонимный uid и refresh token хранятся
  в `%ProgramData%\KidsTimeControl`, доступ только у SYSTEM.
- **Привязка ПК:**
  1. ПК создаёт `pairingRequests/{код}` со своим uid и показывает код из 8 символов (например, `K7QM-4XP2`).
  2. Родитель вводит код в приложении. Приложение читает запрос (список кодов читать нельзя,
     только по точному коду), добавляет uid ПК в `families/{id}.deviceUids`, создаёт
     `devices/{uid}` и удаляет запрос.
  3. ПК находит свою семью запросом `families where deviceUids array-contains <uid>`.
- ПК работает с Firestore через **REST API**: официального Firebase SDK для Windows нет.
  Лимиты, детей и игры ПК забирает раз в минуту, статистику пишет в `usage`, статус — в `devices/{uid}`.
- Статистику за неделю считает приложение родителя по документам `usage`.
- **Правила Firestore**: родитель читает и пишет всё в своей семье. ПК только читает настройки,
  пишет статистику и свой статус. Поменять лимит или PIN с ПК невозможно, и это проверяют тесты.
- Push-уведомления родителю (закончилось время, ПК без связи) отправлять без сервера нельзя.
  Пока приложение показывает эти состояния само, при открытии. Push можно будет добавить позже,
  через Cloud Functions на тарифе Blaze (у него есть бесплатная квота).

Модель данных — в [data-model.md](data-model.md), JSON-схемы — в `shared/schema/`.

## Модель угроз

| Обход | Защита |
|---|---|
| Завершить процесс или службу | у ребёнка нет прав администратора; служба перезапускается |
| Переименовать или скопировать exe игры | сверка пути, позже SHA-256 |
| Изменить системное время | обычный пользователь не может; учёт по монотонным часам |
| Играть под чужим профилем | PIN, блокировка после 5 ошибок, завершение сессии по простою |
| Отключить интернет | ПК работает офлайн; родитель видит пропуск сигналов |
| Безопасный режим, другая ОС | не защищается, это вне рамок |
