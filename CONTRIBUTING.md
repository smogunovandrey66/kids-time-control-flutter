# Как участвовать

1. Обсудите идею в Issues до начала большой работы.
2. Одна задача — одна ветка и один pull request. CI должен быть зелёным.
3. Меняете формат данных — сначала обновите схему в `shared/schema/` и пример в `shared/examples/`,
   затем `ktc_core` и приложения в том же PR. Тест `contracts_test.dart` проверяет, что модели
   читают и пишут примеры без потерь.
4. Всё, что можно проверить без Windows и UI, пишется в `packages/ktc_core` и покрывается тестами.
   В службе и приложениях — только тонкий слой над ядром.
5. Перед коммитом: `dart format .`, `dart analyze`, тесты.
6. Код и комментарии в коде — на английском, документация — на русском.

## Секреты

Никогда не коммитьте `google-services.json`, `firebase_options.dart` с ключами сервисных аккаунтов,
пароли и сертификаты. Для CI они хранятся в GitHub Secrets.
